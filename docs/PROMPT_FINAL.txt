SAFETY RULES:
1. NO destructive exploits — no file deletion, no service crashes,
   no data corruption. CHECK and DETECT only, never destroy.
2. NO DDoS or denial-of-service — no flood attacks, no amplification,
   no resource exhaustion. All scanning must be rate-limited and throttled.
3. BRUTE FORCE SAFETY (every brute/spray module MUST implement ALL):
   - --bf-timeout flag (default 30s per attempt)
   - --bf-delay flag (default 3s between attempts)
   - --bf-max flag (default 3 max attempts per account)
   - Auto-detect account lockout policy BEFORE any spraying
   - Hard stop if attempts reach lockout_threshold - 1
   - Exponential backoff on connection timeout/reset
   - Pattern-match lockout responses: "locked", "too many attempts",
     "banned", "suspended", "temporarily disabled", "account disabled"
   - If >50% connections reset/dropped: auto-switch to stealth timing + alert
   - Log every attempt with ISO 8601 timestamp for full audit trail
4. AUTHORIZATION PROMPT — every tool MUST display at startup:
   ╔══════════════════════════════════════════════════════════╗
   ║  AUTHORIZED PENETRATION TESTING TOOL                    ║
   ║  Confirm written authorization to test this target.     ║
   ║  Type 'yes' to continue or 'no' to exit:               ║
   ╚══════════════════════════════════════════════════════════╝
   Exit code 1 immediately if answer is not exactly "yes".
5. SCOPE ENFORCEMENT — hard-coded scope checker on every outbound
   request, packet, and connection. Any target outside defined scope
   is silently blocked and logged as "out_of_scope" event.
6. ALL ACTIONS LOGGED — every scan, request, finding, attempt, error,
   and operator confirmation decision written to timestamped JSONL log.
   Log format: {"ts": ISO8601, "level": str, "module": str, "event": str,
                "target": str, "detail": dict, "operator_confirmed": bool}
7. LATERAL MOVEMENT CONFIRMATION GATE — for ANY module that would
   execute an active exploitation action (not just detection), ALWAYS
   display and wait for operator confirmation via common/confirm_gate.py:
   ╔══════════════════════════════════════════════════════════╗
   ║  ACTION REQUIRES OPERATOR CONFIRMATION                  ║
   ║  Module  : [module_name]                                ║
   ║  Action  : [what will happen]                           ║
   ║  Target  : [ip/host/object]                             ║
   ║  Risk    : [impact description]                         ║
   ║  Execute this action? (yes/no):                        ║
   ╚══════════════════════════════════════════════════════════╝
   - If "yes": execute, log {"operator_confirmed": true}
   - If "no":  skip, log {"operator_confirmed": false}, still report finding
   - --auto-confirm flag: skip prompts for fully automated pipelines
     (ONLY enable if operator explicitly passes this flag)
   Modules requiring confirmation gate (MUST NOT execute without it):
   WebForge:  login_brute, upload_bypass (payload upload), race_condition
   NetForge:  hydra_wrap, cred_spray, smart_brute, loot_parse (write ops),
              nfs_audit (mount attempt), redis_audit (write check)
   ADForge:   password_spray, kerberoast, asrep_roast, pass_hash,
              pass_ticket, golden_ticket, silver_ticket, dcsync,
              acl_scanner (abuse chain), dacl_abuse, forcechangepw,
              add_member, shadow_creds, smb_exec, wmi_exec,
              secretsdump, loot_collector
8. RATE LIMITING on ALL modules:
   - Default max 10 requests/second per host
   - Configurable via --rate flag (float, 0.1 to 100)
   - Auto-throttle on 429/503 responses (exponential backoff)
   - Per-host rate tracking across all concurrent modules
9. DEPENDENCY PRE-FLIGHT — every tool checks at startup that all
   required external binaries are installed. Print clear install
   command and exit(1) if any are missing.
10. DRY RUN MODE (--dry-run) — show what would run, which targets,
    which phases, but send zero packets. Used for client briefings.

GLOBAL TECHNICAL REQUIREMENTS (ALL FRAMEWORKS)

LANGUAGE + TYPING:
- Python 3.10+, fully typed with type hints everywhere
- PEP 8 compliant, max line length 100
- Dataclasses and Pydantic v2 for all data models
- No untyped dicts — use TypedDict or dataclass for all structured data

STORAGE:
- SQLite for all persistent storage (findings, hosts, creds, runs, events)
- SQLAlchemy 2.0 ORM, schema auto-created via Base.metadata.create_all()
- All sensitive values in DB encrypted with Fernet (cryptography lib)

UI / OUTPUT:
- Rich terminal UI: live tables, progress bars, spinners, panels, syntax highlight
- Phase banners: "═══ PHASE 3/12: INJECTION TESTING ═══" before each phase
- --quiet flag: suppress all UI, structured JSON to stdout only
- --verbose flag: full HTTP request/response debug output

CONCURRENCY:
- asyncio + aiohttp for all HTTP (WebForge)
- asyncio for network scanning (NetForge)
- asyncio + ldap3 async for LDAP (ADForge)
- ThreadPoolExecutor for CPU-bound tasks
- Configurable --workers flag (default 10)

PLUGIN ARCHITECTURE:
- Every module inherits from BaseModule (common/base_module.py)
- BaseModule provides: run(), validate_scope(), log(), save_finding(),
  rate_limit(), check_authorization(), capture_screenshot(), confirm_gate()
- --list-modules shows all available modules + descriptions

CONFIGURATION:
- YAML config file, validated against Pydantic schema at startup
- --config to specify alternate config path
- --generate-config to write default config to disk

RESUME / CHECKPOINT:
- --resume flag: continue from last checkpoint
- Checkpoint saved to SQLite after each phase completes
- Clean Ctrl-C handler: saves checkpoint, exits gracefully

SCREENSHOT / POC EVIDENCE (common/screenshot.py):
- Selenium + system Chromium (pre-installed on Kali)
- Headless, --no-sandbox (Kali runs as root)
- capture(url, wait_ms=1000, highlight_js=None) → screenshot_path
- highlight_js: optional JS snippet to highlight the vulnerable element
  before capture (e.g., highlight an XSS alert box, a reflected payload)
- Screenshots saved to results/evidence/screenshots/finding_{uuid}.png
- Every finding that involves a browser-visible vulnerability MUST
  capture a screenshot as part of evidence
- Modules that MUST capture screenshots:
  WebForge: xss_scanner (show payload rendered), sqli_scanner (show error),
            ssti_scanner (show output), open_redirect (show final URL),
            clickjacking (show framed page), cors_check (show allowed origin),
            403_bypass (show bypassed content), idor_scanner (show data leak),
            login_brute (show successful login), jwt_audit (show auth bypass),
            upload_bypass (show uploaded file accessible), ssrf_scanner,
            header_audit (show missing headers in response), cache_poison
- For non-browser findings (network, AD): capture Rich console panel as
  SVG/HTML using rich.console.Console(record=True) + console.export_html()

REPORTING:
- Jinja2 HTML report (single-file, all CSS/images embedded as base64)
- PDF export via WeasyPrint
- JSON export (DefectDojo/Jira-compatible)
- CSV export (finding name, severity, CVSS, target, status)
- --report-format html,pdf,json,csv (default: html,pdf)

  * reproduction_steps: list[str]

NEW FILE: webforge/core/browser_detect.py
  Purpose: Detect the best available browser on Kali Linux at runtime.
  Priority order (fastest/lightest headless first):
    1. google-chrome / google-chrome-stable  (Chrome)
    2. chromium / chromium-browser           (Chromium — default on Kali)
    3. firefox / firefox-esr                 (Firefox fallback)
  Logic:
    - shutil.which() each binary name in priority order
    - Return a BrowserConfig dataclass:
        type: Literal["chrome", "chromium", "firefox"]
        binary_path: str
        driver_class: type  (webdriver.Chrome | webdriver.Firefox)
        options_class: type (ChromeOptions | FirefoxOptions)
    - For Chrome/Chromium: add --no-sandbox, --headless=new,
        --disable-dev-shm-usage, --disable-gpu, --window-size=1920,1080
    - For Firefox: add -headless, set window size 1920x1080
    - Selenium 4.6+ selenium-manager auto-downloads matching WebDriver —
      no manual chromedriver/geckodriver install needed
    - If NO browser found: print clear apt-get install instructions, exit(1)
    - Export: get_browser_config() → BrowserConfig
               build_driver(config: BrowserConfig, headless: bool = True) → WebDriver

NEW FILE: webforge/core/session_bridge.py
  Purpose: Allow operator to manually complete ANY login type (SSO, MFA,
  CAPTCHA, hardware token, biometric, QR code, Okta/Azure AD/Google
  Workspace/Ping/ADFS, smart card) in a VISIBLE browser, then capture
  the full session so WebForge can continue automated testing.

  How it works:
    1. Opens a VISIBLE (non-headless) browser window using browser_detect.py
    2. Navigates to --login-url
    3. Prints to terminal:
       ╔══════════════════════════════════════════════════════════════╗
       ║  MANUAL LOGIN REQUIRED                                      ║
       ║  Browser window is open. Please complete login now.         ║
       ║  Supports: SSO, MFA, CAPTCHA, QR, Hardware Token,          ║
       ║            Biometric, Smart Card, Okta, Azure AD,           ║
       ║            Google Workspace, Ping, ADFS, and any other.     ║
       ║  When login is COMPLETE and you see the app dashboard,      ║
       ║  press Enter here to capture the session.                   ║
       ╚══════════════════════════════════════════════════════════════╝
    4. input("Press Enter when logged in...") — blocks until operator ready
    5. Captures from the browser:
       - All cookies (name, value, domain, path, secure, httpOnly, sameSite)
       - localStorage keys/values (scan for token, auth, jwt, bearer, access)
       - sessionStorage keys/values (same scan)
       - Common auth header patterns detected in cookies/storage:
         Bearer tokens, JWT tokens, session IDs, CSRF tokens
       - Current URL after login (detect redirect destination)
    6. Saves to --output file (default: session.json):
       {
         "captured_at": ISO8601,
         "login_url": str,
         "post_login_url": str,
         "cookies": [...],
         "localStorage": {...},
         "sessionStorage": {...},
         "detected_tokens": {
           "bearer": str | null,
           "jwt": str | null,
           "csrf": str | null,
           "session_id": str | null
         },
         "selenium_cookies": [...]  # ready for driver.add_cookie()
       }
    7. Prints session summary to terminal (token types found, cookie count)
    8. Browser stays open for 5s then closes (gives operator time to see)

  Integration with WebForge:
    webforge.py --session session.json loads this file and:
    - Injects all cookies into the aiohttp session
    - Sets Authorization header if bearer/jwt token detected
    - Sets X-CSRF-Token header if csrf token detected
    - Uses selenium_cookies to seed the Selenium driver for screenshots
    - All modules then run with the pre-authenticated session

NEW FILE: webforge/session_capture.py  (STANDALONE SCRIPT, not a module)
  Purpose: User runs this BEFORE webforge.py when target uses SSO/complex auth.
  This is a simple CLI wrapper around session_bridge.py.

  Usage:
    python session_capture.py --target https://app.example.com/login
    python session_capture.py --target https://app.example.com/login \
      --output my_session.json --wait-url https://app.example.com/dashboard

  Flags:
    --target        Login URL to open in browser (required)
    --output        Session file path (default: session.json)
    --wait-url      Optional: if provided, auto-detect login completion
                    when browser navigates to this URL (no Enter needed)
    --browser       Force browser: chrome | chromium | firefox (default: auto)
    --timeout       Max wait time for manual login in seconds (default: 300)

  Output:
    - Saves session.json (or --output path)
    - Prints: "Session captured. Run: python webforge.py --target <url> --session session.json"

  Then webforge.py accepts:
    --session session.json          Load pre-captured session
    --sso                           Shortcut: auto-launch session_capture.py
                                    before starting scan, use that session
